# web/: the commit.city site

The hosted builder and the site, deployed to Vercel as-is. It has no framework and no build step:

- `public/`: the static pages;
- `api/`: the functions, as plain web handlers (`export const GET/POST`);
- `vercel.json`: the routes, which map `/<owner>` and `/<owner>/<repo>` onto `api/page`.

```
public/index.html        landing page
public/s/city.{js,css}   the city page's runtime: the builder UI, share sheet and owner settings
public/v/app.<hash>.js   the viewer (generated by viewer/build.mjs)
api/page.ts              /<owner>[/<repo>]: the city page (meta tags, link preview, boot data)
api/build/{start,repo,finish}.ts   the build, driven by the browser: discover → one call per repo → bundle
api/card.ts, api/og.ts   README card (SVG) and link preview (PNG, resvg + Inter)
api/account.ts           /api/auth/*, /api/me, /api/settings: Sign in with GitHub; exclude repos or hide your city
api/site.ts              /api/city, /api/gallery, /api/stars: city status, featured and recent cities, star count
lib/routes/              the handlers behind those two (rewritten to ?op=<name>, so the site fits Hobby's 12 functions)
lib/engine/              git protocol v2 client, pack parser, replay, discovery and bundler (no git binary)
```

## Deploy your own

1. **Create the project.** Import the repo into Vercel with **Root Directory** `web` and the **Other** framework preset. The function limits are in `vercel.json`.
2. **Add storage.** Under **Storage → Create → Blob**, create a **public** store and connect it to the project.
   - The connection adds either `BLOB_READ_WRITE_TOKEN` or OIDC plus `BLOB_STORE_ID`; both work.
   - Everything stored is public GitHub data:

     | Path | Contents |
     |---|---|
     | `cities/` | payloads |
     | `meta/` | city metadata |
     | `sky/` | skylines for cards and previews |
     | `repos/` | per-repo records, keyed by head commit |
     | `settings/` | owner choices |
     | `gallery/` | featured and recent cities |
3. **Add a GitHub token.** Create a [fine-grained PAT](https://github.com/settings/personal-access-tokens/new) with **Public repositories (read-only)** access and no permissions, and set it as `GITHUB_TOKEN`.
   - The token is used for GraphQL discovery and git fetches.
   - It can only read what is already public. It gets 5,000 GraphQL points an hour; a city costs roughly 2 to 30.
4. **Add Sign in with GitHub** (optional, for the owner controls).
   - Create an [OAuth App](https://github.com/settings/applications/new) with the callback `https://<your domain>/api/auth/callback`.
   - Set `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET`. No scopes are requested.
5. **Set `SITE_URL`** to `https://<your domain>`. It's used for canonical URLs, link previews and the OAuth redirect.
6. **Signing secret (optional):** `COMMIT_CITY_SECRET`.
   - Build tickets and sessions are signed with a key derived from `COMMIT_CITY_SECRET`. If that's unset, the key comes from the Blob token or the OAuth client secret instead.
   - Set it explicitly if you want to rotate sessions independently.

| Variable | Required | What |
|---|---|---|
| `GITHUB_TOKEN` | yes | fine-grained PAT, public repositories read-only |
| `BLOB_READ_WRITE_TOKEN` or `BLOB_STORE_ID` | yes | added by connecting a public Blob store |
| `SITE_URL` | yes | e.g. `https://commit.city` |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | for sign-in | OAuth App |
| `COMMIT_CITY_SECRET` | no | signing key material (32+ random bytes) |

**Costs.**

- **Function time:** a repo replay is mostly waiting on GitHub to compute a pack, which is cheap in Active CPU. Big histories, like a whole-history `?all=1` city, are the expensive case.
- **Function limits:** each replay call gets up to 300 s and 2 GB, which is enough for repos up to ~1.5 GB on disk (the discovery cap).
- **Storage:** a city payload is usually 50 KB to 2 MB gzipped, and repo records are shared between cities.
- **Hobby plan:** fine to try it out, but it's for non-commercial use, and its Blob operation quotas lock the store for 30 days once exceeded. Use Pro for a public launch.
- **Rate limits:** add a firewall rate limit on `/api/build/*` (for example 60 requests a minute per IP) before announcing anything.

## Develop

```bash
npm ci
npm test                                         # engine + bundle, incl. parity with the Python replay
GITHUB_TOKEN=$(gh auth token) node scripts/dev.mjs 3000
```

`scripts/dev.mjs` is a small local stand-in for Vercel:

- it applies the `vercel.json` rewrites and headers and serves `public/`;
- it bundles each function on demand with esbuild, and reloads when the function or anything in `lib/` changes;
- it stores cities in `.local-store/`.

Your `gh` token is fine locally, but don't deploy it: production should use the read-only PAT above.

`scripts/build-city.mjs <base url> <target> [--all]` drives a build through the public API exactly as the page does. It's useful for prewarming cities and for end-to-end checks of a deployment:

```bash
node scripts/build-city.mjs http://localhost:3000 sindresorhus
node scripts/build-city.mjs https://commit.city facebook/react
```

Network tests (live parity against a full clone; GraphQL discovery) are opt-in:

```bash
LIVE=1 LIVE_REPOS=sindresorhus/ky,vitejs/vite npm test -- live
DISCOVER=sindresorhus,vercel,facebook/react npm test -- discover
```
